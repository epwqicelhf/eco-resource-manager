# 生态资源管理系统 - 测试框架

## 概述

本测试框架为生态资源管理系统提供全面的自动化测试支持，包括功能测试、边界值测试和异常测试。测试框架具有以下特点：

- **数据库隔离**: 每次测试前自动重置数据库，确保测试环境干净
- **结构化报告**: 生成详细的JSON格式测试报告和追溯矩阵
- **HTML可视化报告**: 生成美观的HTML格式测试报告，支持查看详细结果
- **多运行汇总**: 自动生成测试报告汇总索引页，追踪历史测试运行记录
- **测试分类**: 按模块和测试类型组织测试用例
- **可追溯性**: 每个测试用例都有明确的预期结果和实际结果对比

## 目录结构

```
tests/
├── TEST_STRATEGY.md          # 测试策略文档
├── cases.js                  # 测试用例定义
├── runner.cjs                # 测试运行器
├── excel-helper.cjs          # Excel测试数据生成辅助
├── README.md                 # 本文件
└── reports/                  # 测试报告输出目录
    ├── index.html            # 测试报告汇总索引（最新）
    ├── summary.json          # 测试运行历史记录
    ├── test-report-*.json    # 每次运行的测试报告
    ├── test-report-*.html    # 每次运行的HTML格式报告
    └── traceability-*.json   # 每次运行的追溯矩阵
```

## 运行测试

### 基本运行

```bash
npm test
```

或者

```bash
node tests/runner.cjs
```

### 测试输出

测试运行器会输出：
- 实时测试进度
- 每个测试用例的执行状态（✓ 通过, ✗ 失败, ○ 跳过）
- 失败测试的详细错误信息
- 测试摘要统计
- 报告文件路径

### 测试报告

测试完成后，会在 `tests/reports/` 目录下生成多个文件：

1. **index.html**: 测试报告汇总索引页，包括：
   - 所有历史测试运行的统计概览
   - 每次运行的通过率趋势图
   - 快速链接到各次运行的详细报告
   - 最新运行结果高亮显示

2. **summary.json**: 测试运行历史记录，用于生成汇总索引

3. **test-report-{timestamp}.json**: 详细的测试报告，包括：
   - 测试摘要（总数、通过、失败、跳过、通过率）
   - 按模块分类的测试结果
   - 按测试类型分类的测试结果
   - 每个测试用例的详细信息（预期结果、实际结果、执行时间、错误信息）

4. **test-report-{timestamp}.html**: HTML格式的可视化测试报告，包括：
   - 美观的统计图表
   - 模块测试结果卡片
   - 详细的测试用例列表
   - 测试追溯矩阵（已优化表格溢出问题）
   - 失败用例的详细信息

5. **traceability-{timestamp}.json**: 测试追溯矩阵，包括：
   - 测试用例ID
   - 测试用例名称
   - 所属模块
   - 测试类型
   - 优先级
   - 执行状态
   - 预期结果
   - 实际结果
   - 错误信息

## 测试用例结构

测试用例定义在 `cases.js` 文件中，按模块组织：

```javascript
{
  id: 'ORG-001',                    // 唯一标识符
  name: '创建一级组织',              // 测试用例名称
  type: 'functional',               // 测试类型: functional/boundary/exception
  priority: 'high',                 // 优先级: high/medium/low
  description: '验证可以成功创建一级组织',  // 描述
  precondition: '系统已启动，数据库为空',   // 前置条件
  steps: [                          // 测试步骤
    'POST /api/orgs',
    '请求体: { name: "测试集团", parent_id: null }'
  ],
  expected: {                       // 预期结果
    status: 200,
    body: { id: 'positive_integer', name: '测试集团', level: 1, parent_id: null }
  }
}
```

## 测试模块

### 1. 组织管理 (ORG)
- 创建多级组织
- 组织名称验证
- 父组织验证
- 删除组织
- 查询组织树

### 2. 总表管理 (GLB)
- 创建总表数据
- 字段验证（必填、范围1-5、整数）
- 重复数据项验证
- 更新和删除总表数据
- 查询总表数据

### 3. 组织级隐私数据 (PRIV)
- GUI新增隐私数据
- 非叶子组织限制
- 组织不存在验证
- 重复数据项验证
- 更新和删除隐私数据
- 查询组织隐私数据

### 4. 数据导入 (IMP)
- 正常导入Excel
- 空文件处理
- 缺少必填字段处理
- 重复数据项处理
- 组织分类列处理
- 下载导入模板

### 5. 数据审核 (REV)
- 查询待审核数据
- 审核通过
- 审核驳回
- 批量审核
- 审核不存在的数据

### 6. 整改任务 (REC)
- 修改总表触发整改任务
- 查询整改任务
- 确认整改任务
- 批量确认整改
- 忽略整改任务

### 7. 审计日志 (AUD)
- 查询审计日志
- 按组织筛选日志
- 回退预览
- 执行回退
- 审计日志上限

### 8. 数据下发 (DST)
- 下发总表数据到组织
- 下发到非叶子组织
- 下发已存在的数据

### 9. 冲突检查 (CNF)
- 执行冲突检查
- 应用冲突修复
- 无冲突时检查

### 10. 统计汇总 (SUM)
- 查询汇总统计
- 统计整改任务

## 测试类型

### 功能测试 (functional)
验证系统功能按照需求规格正确实现。

### 边界值测试 (boundary)
验证系统在边界条件下的行为，如：
- 等级字段的最小值(1)和最大值(5)
- 超出范围的值(0, 6)
- 非整数值(3.5)

### 异常测试 (exception)
验证系统对异常输入的处理，如：
- 空字段
- 不存在的数据
- 重复数据
- 权限限制

## 测试最佳实践

1. **保持测试独立性**: 每个测试用例应该独立运行，不依赖其他测试的结果
2. **清理测试数据**: 测试运行器会在每次测试前重置数据库
3. **使用有意义的断言**: 断言消息应该清晰说明预期和实际的差异
4. **覆盖边界条件**: 确保测试覆盖所有边界值和异常情况
5. **维护测试文档**: 及时更新测试用例和测试策略文档
6. **查看HTML报告**: 使用 `tests/reports/index.html` 查看历史测试运行汇总，追踪测试结果趋势
7. **检查追溯矩阵**: HTML报告中的追溯矩阵已优化表格布局，长文本会自动截断并显示省略号，鼠标悬停可查看完整内容

## 测试报告可视化

### HTML报告特性

测试框架自动生成美观的HTML格式测试报告，具有以下特性：

1. **汇总索引页** (`index.html`)
   - 显示所有历史测试运行的统计概览
   - 每次运行的通过率趋势图
   - 快速链接到各次运行的详细报告
   - 最新运行结果高亮显示
   - 支持按通过率排序和筛选

2. **单次运行详细报告** (`test-report-{timestamp}.html`)
   - 美观的统计图表（饼图、柱状图）
   - 模块测试结果卡片，直观展示各模块通过情况
   - 详细的测试用例列表，支持按状态筛选
   - 测试追溯矩阵，展示预期结果与实际结果的对比
   - 失败用例的详细错误信息和堆栈跟踪

3. **追溯矩阵优化**
   - 表格采用固定布局，防止内容溢出
   - 长文本自动截断并显示省略号
   - 鼠标悬停可查看完整的JSON内容
   - 支持响应式设计，适配不同屏幕尺寸

### 查看报告

1. 打开 `tests/reports/index.html` 查看汇总索引
2. 点击任意一次运行的链接查看详细报告
3. 在详细报告中使用搜索和筛选功能定位特定测试用例

## 故障排查

### 测试失败

1. 查看测试报告中的详细错误信息
2. 检查预期结果和实际结果的差异
3. 验证API端点是否正常工作
4. 检查数据库状态是否正确

### 服务器启动失败

1. 检查端口3001是否被占用
2. 查看服务器日志输出
3. 验证数据库文件是否正确删除

### 测试超时

1. 增加测试超时时间
2. 检查是否有长时间运行的操作
3. 优化测试用例的执行效率

## 扩展测试

### 添加新的测试用例

1. 在 `cases.js` 中添加测试用例定义
2. 在 `runner.cjs` 的 `runTestCaseLogic` 函数中添加测试逻辑
3. 运行测试并验证结果

### 添加新的测试模块

1. 在 `cases.js` 中添加新的模块定义
2. 在 `runner.cjs` 中添加模块的测试逻辑
3. 更新测试策略文档

## 持续集成

建议将测试集成到CI/CD流程中：

```yaml
# .github/workflows/test.yml
name: Test
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - uses: actions/setup-node@v2
        with:
          node-version: '18'
      - run: npm install
      - run: npm run build
      - run: npm test
      - name: Upload test reports
        uses: actions/upload-artifact@v2
        with:
          name: test-reports
          path: tests/reports/
```

**CI/CD集成说明**：
- 测试报告会自动上传为构建产物
- 可通过 `tests/reports/index.html` 查看历史测试运行汇总
- 每次运行都会生成独立的HTML报告和追溯矩阵
- 追溯矩阵表格已优化，长文本会自动截断并支持悬停查看完整内容
